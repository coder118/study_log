## 2. `DispatcherServlet` 인스턴스 생성 및 스프링 구동 단계 (Instantiation & Init)

### 2.1. 서블릿 로딩 타이밍 결정

* **지연 로딩 (Lazy Loading - 기본값):** 서버가 뜰 때는 대기하다가, **최초의 HTTP 요청이 들어오는 순간** 로딩이 트리거됩니다.
* **즉시 로딩 (Load-on-Startup):** 설정에 따라 서버가 켜지는 시점에 미리 로딩을 수행하도록 지정할 수 있습니다.

### 2.2. 톰캣에 의한 `DispatcherServlet` 객체 생성 (`loadServlet`)

* **`InstanceManager`의 리플렉션:** 톰캣의 `StandardWrapper.loadServlet()` 메서드가 호출됩니다.
* **인스턴스 탄생:** 톰캣 내부의 `InstanceManager`가 자바 리플렉션을 이용해 메모리에 `new DispatcherServlet()`을 직접 생성합니다.


### 2.3. `init()` 호출과 스프링 IoC 컨테이너 구동

* **서블릿 초기화 신호:** 톰캣이 `DispatcherServlet`의 부모 클래스 규격에 맞춰 `init()` 메서드를 호출합니다.
* **스프링 컨테이너 빌드:** 이 순간 `DispatcherServlet` 내부에서 스프링의 `WebApplicationContext`가 스스로 구동되며, 개발자가 작성한 `@Controller`, `@Service` 등의 빈(Bean)들을 스캔하고 등록하여 요청 맞춤 준비를 마칩니다.

## 3. 클라이언트 요청 수신 및 실행 단계 (Request Processing)

### 3.1. 커넥터(Coyote)를 통한 HTTP 요청 유입

* **네트워크 통신:** 클라이언트가 요청을 보내면 톰캣의 Coyote Connector가 이를 받아 `Engine` ➔ `Host` ➔ `Context` 순으로 전달합니다.

### 3.2. Wrapper Valve와 `allocate()`의 작동

* **파이프라인 통과:** 요청이 최종 목적지인 `StandardWrapper`의 `Pipeline`에 도달하고, 마지막 관문인 `StandardWrapperValve`의 `invoke()` 메서드가 실행됩니다.
* **서블릿 할당:** `allocate()` 메서드가 호출되어, 앞서 만들어두었던 `DispatcherServlet` 인스턴스가 안전하게 호출 대기 상태로 준비됩니다.

### 3.3. `DispatcherServlet`의 요청 접수 및 스프링 매핑 (`doDispatch`)

* **`service()` 호출:** 톰캣의 Valve가 `DispatcherServlet`의 `service()` 메서드를 호출하면서 표준 객체(`HttpServletRequest`, `HttpServletResponse`)를 넘겨줍니다.
* **스프링의 세상으로 전환:** `DispatcherServlet` 내부의 `doDispatch()` 메서드가 동작하여, 들어온 HTTP 메서드와 URL에 알맞은 개발자의 **스프링 `@Controller`를 매핑하고 실행**한 뒤 응답을 돌려줍니다.

## 4. 서버 종료 단계 (Lifecycle Termination)

### 4.1. 서블릿 파괴 및 자원 해제 (`unload`)

* 서버가 종료되거나 웹앱이 내려갈 때, 톰캣은 `StandardWrapper.unload()`를 호출합니다.
* 내부에 있던 `DispatcherServlet`의 `destroy()`가 실행되며 스프링 컨테이너가 품고 있던 빈들과 자원들이 안전하게 해제됩니다.
